# Mesh FBX export

The Mesh Viewer export dropdown includes **Export mesh to FBX...**. Select a data
stage (VS Input, VS Output or geometry/mesh output) and instance first. The dialog
uses an editable table with Usage, Source attribute, First component and Export
name. Select exactly one Position XYZ source. Optional usages are Normal XYZ,
Tangent XYZ(W), Binormal XYZ, UV XY, Color RGB(A) and Custom data. Use **Add
attribute set** to add any number of sets, or **Add unmapped sources as custom
data** to retain the remaining numeric attributes. Rows with source None are omitted.
Each exported set requires a unique name. Name-based suggestions include all
detected UV/color sources and remain editable. Mappings apply to this export.
CSV and byte export remain available.

Each mapping also has four opt-in conversion checkboxes (all off by default):
**XYZ remap** applies `value * 2 - 1` to the first three exported components (or
both components for UV). **Normalize XYZ** normalizes those three components after
remapping and rejects zero-length directions. **Tangent W remap** independently
converts the fourth tangent component; XYZ normalization never changes W.
These operate on decoded values, so UNorm inputs first decode to [0,1]. Enable
remapping only when that is the source's encoding; SNorm or already-decoded shader
outputs normally need no remapping. This is not octahedral or other compressed
normal decoding. **Flip V** is available only for UV mappings and applies
`V = 1 - V` after other conversions, leaving U unchanged. Each UV set can be
flipped independently; values outside [0,1] are not clamped. Use it when the
destination's UV/image convention requires a vertical flip, not automatically
based on the capture API. Batch layout mappings and reports retain all four options.

Rows size to their editors and scroll as a single table. The mouse wheel over a
usage/source selector or component input scrolls the table without changing the
value; click to select or type to edit. An opened dropdown list can still scroll.

For example, map TEXCOORD0 XY to UV0 with First component 0, and TEXCOORD0 ZW to
UV1 with First component 2. Additional TEXCOORD attributes can each have their
own UV set. Multiple normal, tangent, binormal and color sets are also allowed.
For tangent mappings, **Handedness source** defaults to the tangent source's
fourth exported component. Select another source and an X/Y/Z/W **Handedness
component** to assemble tangent XYZ and handedness from different attributes.
This also supports three-component tangent sources. The independent value uses
its own source format and vertex/instance rate, then **Tangent W remap** applies
to it; XYZ remapping/normalization does not modify handedness. For EID 16735,
map tangent XYZ from ATTRIBUTE1, select ATTRIBUTE2 / W for handedness, and enable
XYZ remap and Tangent W remap. Configure the normal separately from ATTRIBUTE2 XYZ.
Batch layouts retain and match both sources by attribute identity; reports record
the independent source identity and component (0=X through 3=W). No binormal is
generated by this option.

Tangent W is preserved in a custom scalar named `<set>.w`, because FBX tangent
layer serialization only retains XYZ; importers may need custom handling to use
this handedness. RGB colors default to alpha 1. FBX colors clamp channels to
[0, 1]; map HDR or other unrestricted values to Custom instead.

Custom scalar/vector/matrix components are stored in FBX UserData as individual
double arrays named `<set>.0`, `<set>.1`, etc., starting at the selected component.
This can preserve weights, bone indices, velocities or other numeric payloads,
but does not create a skin deformer: skeleton hierarchy and bind transforms are
not available from these attributes alone. DCC importers may ignore UserData.
Integers outside [-2^53, 2^53] are rejected to avoid silent precision loss.

Export supports complete triangle lists, strips and fans, including primitive
restart and alternating strip winding. Control points are shared by source index,
not position, preserving attribute seams. Degenerate triangles are omitted.
Missing, out-of-range and non-finite data abort export. Other topologies and
incomplete datasets are rejected. Per-primitive and generic constant attributes
are not selectable. One mesh and the selected instance are exported;
materials, textures, skeletons and animation are not reconstructed.

Values use RenderDoc's format decoder (including packed and normalized formats),
not formatted table text. No axis conversion, unit scaling, perspective divide,
normal reconstruction is applied. UVs are unchanged unless an explicit conversion
is enabled. Shader outputs can be clip-space
values; mapping them to Position does not recover model-space geometry.

## Batch export

In Event Browser, select draw events with Ctrl/Shift, or select a marker group,
then choose **Batch export meshes to FBX...** from the context menu. Groups include
their nested draw events. The dialog also accepts comma-separated event IDs and
inclusive ranges such as `12, 40-80`; non-draw events are excluded, and overlapping
ranges do not duplicate draws.

1. Select VS Input, VS Output, or Geometry/Domain/Mesh Output. There is no automatic
   fallback when a stage is unavailable. Multi-view captures currently use view 0.
2. Select one instance by its zero-based index, or choose all instances.
3. Click **Preflight** to list events, counts, layout groups and unsupported cases.
4. Select an event row, click **Configure selected layout...**, and map the attributes.
   Repeat for each layout you want to export. Uncheck unwanted events. Save becomes
   available when every checked event has a configured layout.
5. Click Save and select a directory. Existing files are skipped unless overwrite
   was explicitly enabled in the dialog.

Layouts match by attribute identity, format, component count and data frequency.
Column order does not matter: stored identities are resolved against each event's
columns before export. Ambiguous duplicate identities are rejected. Changing stage,
instance settings or event range requires preflight again.

Each event/instance produces a separate FBX, for example
`EID_001240_DrawIndexed_S0_I0.fbx`. S0/S1/S2 identify the three stage choices.
There is no model deduplication or merging across passes. A unique
`export_report_<id>.json` records the capture, events, instances, mappings, file
names, outcomes and reasons. Failed events do not prevent later events from running.

Progress displays the current event. Cancellation stops subsequent work after the
current file operation returns and preserves completed files. Replay runs serially,
releases each mesh's buffers before the next instance, and restores the original
replay event after preflight and export; the UI selection is not changed. Very large
bound vertex buffers can still require substantial memory for one event.

VS Input does not reconstruct per-instance world transforms or shader deformation.
The geometry and custom-data limitations described above apply to batch exports too.

## Build

Install the [Autodesk FBX C++ SDK](https://aps.autodesk.com/developer/overview/fbx-sdk)
separately under its supplied license. SDK binaries are not included in this repo.
Without the SDK, the export action explains how to enable support.

For Visual Studio/MSBuild, pass `FBXSDKRoot` (directory containing `include`) and
`FBXSDKLibraryDir` (SDK release libraries matching compiler and architecture).
The optional `fbx.props` links the static `/MD` SDK, XML, zlib and Windows system libraries:

```powershell
msbuild renderdoc.sln /m /p:Configuration=Development /p:Platform=x64 '/p:FBXSDKRoot=C:\SDK\FBX' '/p:FBXSDKLibraryDir=C:\SDK\FBX\lib\x64\release'
```

SDK 2020.3.10 uses `lib/x64/release`; older SDKs may include a toolset directory.
For persistent local Visual Studio builds, put these two properties in
`qrenderdoc_local.vcxproj.user`, scoped to the matching platform. This file is
ignored by Git, so the local SDK installation path is not shared with the repo.

For qmake (including the
CMake qmake wrapper), set `FBXSDK_ROOT` and `FBXSDK_LIBS` in the environment before
configuring. `FBXSDK_LIBS` contains the platform-specific SDK linker flags and
dependencies; use the SDK sample projects as a reference.

## Validation

The Development build includes `[fbx]` tests that exercise the same export
function as the UI and import the resulting files using the SDK:

```powershell
$test = Start-Process -FilePath .\x64\Development\qrenderdoc.exe -ArgumentList '--unittest','log=fbx-tests.log','[fbx]' -WindowStyle Hidden -Wait -PassThru
$test.ExitCode
```

On 2026-09-10, the Windows x64 Development build compiled and linked against
FBX SDK 2020.3.10, and the SDK round-trip tests passed. Cases cover indexed UV
seams, strips with restart, fans, negative base vertex, non-indexed positions,
packed normalized normals, per-instance UVs, Unicode filenames and failure
without overwriting the destination. Interactive capture export and DCC import
remain manual checks; the automated fixtures do not replay a capture.
Extended fixtures also round-trip ten named UV sets, XY/ZW component selection,
tangent XYZ and handedness, binormals, two color sets and custom data, and reject
duplicate names or insufficient components.

Batch tests are included in `[fbx]`. An additional `[fbx-capture]` integration test
can open a simple D3D11 fixture supplied through `RENDERDOC_FBX_TEST_CAPTURE`. On
2026-09-11 a generated fixture with non-indexed, indexed and instanced triangle draws
was replayed through the actual batch data path. Tests exercised VS Input/Output,
layout matching, instance export, existing-file skips, failure continuation,
cancellation before execution, and restoring replay buffer contents. Interactive
dialog operation, cancellation during a long driver call, other graphics APIs and
geometry/mesh shader output still require manual/integration coverage.

Export an indexed mesh with known positions, normals and UV seams; import it
with the SDK or a DCC and compare decoded attributes and triangle winding.
Repeat with strips (including restart), fans, base vertex, instance attributes,
packed formats and shader output remapped indices. Check that bad buffers fail
without replacing an existing destination. Also build without SDK support.
